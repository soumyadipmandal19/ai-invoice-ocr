# Common bill dataset — version 1

Every bill uses the same model regardless of its original document layout.

## Open the Excel files

- [Blank workbook](../../public/templates/bills-template.xlsx): start recording bills.
- [Example dataset](example.json): two fictional bills and three items.

The blank workbook has **Instructions**, **Bills**, and **Bill Items** sheets and
is available from the upload panel in the application. It is a real `.xlsx` file.
CSV templates for Products and Receipts are generated on demand in the sheet UI.

The Instructions sheet opens with a short three-step guide and direct links to
Bills and Bill Items. Data sheets use dark green headers, banded Excel tables,
25 formatted blank rows, frozen headers and identifiers, and readable column
widths. Review Status has an amber/green indicator and dropdown. Dates, amounts,
and text identifiers retain their original column formats. Grid lines are hidden
in favor of light cell borders; print output uses landscape layout.

The example illustrates:

| Bill ID | Bill number | Vendor | Item | Line total |
| --- | --- | --- | --- | ---: |
| B001 | INV-00101 | ABC Stationery | Notebook | 708.00 |
| B001 | INV-00101 | ABC Stationery | Pen | 472.00 |
| B002 | INV-00102 | XYZ Office Supplies | Folder | 500.00 |

B001's bill total is 1180.00 and B002's is 500.00. Full bill totals occur once in
**Bills**, not on every item. Each item repeats the bill number, vendor, bill
date, and currency for readable exports; those values come from its parent bill.

## Files and ownership

| File | Responsibility |
| --- | --- |
| [`types/bills/models.ts`](../../types/bills/models.ts) | Shared canonical bill, item, and dataset types |
| [`schema.ts`](../../lib/server/database/schema.ts) | Central persisted models `BillNode` and `BillItemNode` |
| [`example.json`](example.json) | Complete fictional example in the canonical format |
| [`columns.json`](columns.json) | Workbook headers, ordering, and cell types |
| [`build_bill_workbooks.py`](../../scripts/datasets/build_bill_workbooks.py) | Validate the example dataset and rebuild the blank workbook without extra dependencies |

The dataset envelope has `schemaVersion: 1`, a `bills` array, and an `items` array.
`ownerUserId` is internal application metadata. Future save endpoints must assign
it from the verified session, never trust an owner ID supplied by a browser.
The workbooks intentionally exclude user IDs and internal save timestamps.
Example IDs and dates are illustrative; production IDs must be generated by the
server and remain stable when a record is edited.

The example dataset never seeds Aura or create example accounts. Successful
Inngest financial results now use this format for automatic Neo4j persistence;
`POST /api/bills` can retry a staged save. The existing financial CSV exports
retain their original column format. Later spreadsheet edits are not yet saved
back to Neo4j.

## Bills — one record per bill

| Field | Type | Meaning |
| --- | --- | --- |
| billId | string | Stable unique bill ID; joins items to this bill |
| ownerUserId | string | Signed-in user's ID; internal only |
| billNumber | string or null | Printed number; preserve leading zeros |
| billDate | date string or null | Confirmed YYYY-MM-DD date |
| originalBillDate | string or null | Original extracted date, including ambiguous dates |
| vendorName | string or null | Seller/supplier/merchant name |
| vendorTaxId | string or null | Vendor tax identifier |
| customerName | string or null | Buyer name |
| currency | string or null | Confirmed three-letter code, e.g. INR |
| subtotal | number or null | Printed subtotal |
| discountAmount | number or null | Bill-level discount, not a percentage |
| taxAmount | number or null | Bill-level tax |
| shippingAmount | number or null | Bill-level delivery charge |
| totalAmount | number or null | Final bill total |
| amountPaid | number or null | Confirmed payment amount |
| balanceDue | number or null | Outstanding amount |
| paymentMethod | string or null | Printed/confirmed payment method |
| reviewStatus | enum | Needs review or Reviewed |
| notes | string or null | Review notes, ambiguity, reconciliation differences |
| sourceFile | string | Original filename |
| createdAt | timestamp string | UTC ISO timestamp of first save |
| updatedAt | timestamp string | UTC ISO timestamp of last save |

## Bill Items — one record per purchased item

| Field | Type | Meaning |
| --- | --- | --- |
| itemId | string | Stable unique item ID |
| billId | string | Must reference an existing bill |
| itemNumber | positive integer | Unique position within this bill |
| description | string or null | Product or service description |
| productCode | string or null | Preserve codes such as 00010 as text |
| category | string or null | Supported/reviewed category |
| quantity | number or null | May be fractional; leave unknown quantities blank |
| unit | string or null | pcs, kg, hours, etc. |
| unitPrice | number or null | Unit price as documented |
| discountAmount | number or null | Item discount amount |
| discountRate | number or null | Percentage points: 5 means 5% |
| taxRate | number or null | Percentage points: 18 means 18% |
| taxAmount | number or null | Item tax amount |
| lineTotal | number or null | Item final total as documented |
| sourcePage | positive integer or null | Page containing the source item |
| reviewStatus | enum | Needs review or Reviewed |
| notes | string or null | Item interpretation/review notes |

## Recording rules

- Unknown extracted fields are **null** in JSON and blank in Excel. Zero means
  the amount/rate is confirmed to be zero. Do not guess missing quantities or tax.
- IDs, bill numbers, product codes, and tax identifiers remain text.
- Dates must be unambiguous before filling `billDate`. Keep the original date text
  and flag ambiguity in notes. Excel exports use native date cells with
  `yyyy-mm-dd` display formatting.
- Monetary values are numbers without currency symbols. Currency is separate.
  Do not mix currencies when summing amounts. Exact arithmetic/rounding policies
  must be chosen before adding financial calculations;
  JavaScript numbers are not arbitrary-precision decimal accounting values.
- Bills may use inclusive or exclusive tax, discounts, or rounding. Store printed
  values and review discrepancies rather than overwriting totals with a guessed
  formula. The fictional example explicitly uses tax-exclusive prices.
- A bill can have no detected items; do not invent one to fill the items sheet.
- Reuse Bill ID and Item ID when saving corrections. Flag possible repeated bills
  using vendor, printed bill number, and date; detection is a separate feature.
- Review states start at **Needs review** and change to **Reviewed** after checking.
- Keep each bill's items together, ordered by Item Number.

## Workbook navigation

Use **View Items** on Bills to jump to the first item. Use **Bill ID** filters on
Bill Items to show only that bill. **Back to Bill** returns to its summary.
Headers and the first identifier column stay frozen. Review Status has a dropdown.

Populated workbook navigation links point to exported row locations. Manual row sorting,
insertion, or deletion can change those locations; use Bill ID filtering after
such changes. Regenerating the workbook rebuilds the links. The blank template
has no bill-to-item links until data is populated/exported; matching Bill IDs still provide
the connection. Extend the filter range after adding rows manually, or use
Excel tables expand during normal entry; check filter coverage in other spreadsheet apps. Input validation covers rows 2–10000.

## Mapping from current OCR financial sheets

| Current field | Common bill field |
| --- | --- |
| document_id | billId (stable document identity must be assigned on first save) |
| document_number | billNumber |
| document_date | billDate only after date normalization; otherwise originalBillDate |
| merchant_name / merchant_tax_id | vendorName / vendorTaxId |
| discount / tax / shipping / total | discountAmount / taxAmount / shippingAmount / totalAmount |
| amount_paid / balance_due | amountPaid / balanceDue |
| product_name / product_code | description / productCode |
| line_number / source_page | itemNumber / sourcePage |
| unit_price / line_total | unitPrice / lineTotal |
| discount_rate / tax_rate | discountRate / taxRate |
| review_status / source_file | reviewStatus / sourceFile |

The current OCR sheets hold extracted values as strings. The save step parses
only plain decimal numbers, percentage values with an optional percent suffix,
and unambiguous ISO dates. Other values remain in the raw saved workbook, with
null normalized fields and review warnings. The current workflow job ID changes on repeated
uploads; it is not a duplicate-detection rule. The automatic persistence implementation is in `lib/server/bills/`.

Rebuild the blank workbook with:

```bash
python3 scripts/datasets/build_bill_workbooks.py
```
